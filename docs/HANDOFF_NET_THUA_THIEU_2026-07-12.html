Bối cảnh 1 câu

Giao dịch quẹt thẻ/trả góp có phí → hệ thống cũ tính thừa/thiếu trên gross (số khách chuyển) → phí bị nhầm thành "khách trả dư". Sửa lại: thừa/thiếu = net − dự kiến (net = tiền thực nhận sau phí, kế toán điền khi ghép mPOS).

Quy tắc LÕI (cả BE + FE phải KHỚP)

netCủaLine(line):
  NẾU method ∈ {"card", "installment"} VÀ verified_received != null
    → return verified_received
  NGƯỢC LẠI → return amount (gross)

received = SUM(netCủaLine) cho các line status="paid", chưa hủy
delta = received − target
state: received≤0 → pending | <target → short | =target → done | >target → over
phí (hiển thị) = gross − net (clamp ≥ 0)
⚠️ Code FE hiện CHỈ check installment — thiếu card. Phải thêm.

export function lineNet(p: PaymentAttempt): number {

export function feeTotal(pr: PaymentRequest): number {
  return Math.max(0, grossReceived(pr) - displayReceived(pr));

Anti-patterns (đừng làm)

  1. ❌ KHÔNG tạo bảng phí% hay config phí theo phương thức — anh Hiếu chốt không cần.
  2. ❌ KHÔNG thêm migration — cột verified_received, verified_total đã có sẵn.
  3. ❌ KHÔNG đổi luồng kế toán ghép mPOS — chỉ dùng lại output net.
  4. ❌ KHÔNG để 1 chỗ tính gross 1 chỗ tính net (nguồn lệch cũ).
  5. ❌ KHÔNG revoke/lock activation khi state tụt short sau ghép.
