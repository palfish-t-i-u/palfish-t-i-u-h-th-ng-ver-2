# Pydantic leftover constraint after gating removal

**Related files:** `backend/activation_routes.py`, `frontend/src/components/payment-request/PaymentRequestDetailDrawer.tsx`

**Problem:** Clearing UID/phone on an AR via PATCH silently failed — UI reverted to old values, no DingTalk notification fired.

**Trap:** Searching only the Python helper functions (`_assert_uids_have_uid`, `arRowsValid`) when removing a validation gate, and missing the Pydantic model that also enforces the same constraint via `Field(..., min_length=1)`. Pydantic validation fires BEFORE any route code runs — the 422 never reaches the route body, so no log appears in route-level error handling.

**Insight:** Pydantic `Field(min_length=1)` on `ActiveRequestPatchUidPayload.uid` was a second, independent enforcement of "uid required" that survived the 70c0d4f commit which removed the explicit gate. Pydantic model validation is invisible to route-level try/catch — the 422 is auto-generated by FastAPI before the handler executes. The FE catch block showed a generic "máy chủ chưa lưu được" message, not the actual validation error.

**Rule:** When removing a business validation (e.g. "field X required"), grep for ALL enforcement points: (1) explicit `assert`/`raise` in route code, (2) Pydantic `Field(min_length, ge, regex...)` on the model, (3) FE form validation, (4) DB constraints. Run `grep -n 'min_length\|max_length\|ge=\|le=\|regex=' backend/activation_routes.py | head -20` after any gating removal to check for leftover Pydantic constraints.

**Verify:** `python -c "from pydantic import BaseModel; exec(open('backend/activation_routes.py').read().split('class ActiveRequestPatchUidPayload')[1].split('class ')[0])"` — or simpler: `grep 'uid:' backend/activation_routes.py | head -3` should show `uid: str = ""` (no min_length).
